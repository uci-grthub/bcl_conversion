Set up a cron job that waits for CopyComplete.txt, then runs `pixi run all` followed by
`pixi run publish`, exactly once, directly from cron (no tmux).

run_when_ready.sh handles everything: it reads data_dir from snakemake_config_project.yaml,
exits quietly until CopyComplete.txt appears in data_dir, then runs `pixi run all` and, only
if that succeeds, `pixi run publish`. pixi activation loads .env and sets
SNAKEMAKE_PROFILE=profiles/default, so no --profile flag or manual env sourcing is needed.

1. Ensure 'data_dir' is set in snakemake_config_project.yaml, e.g.:
     data_dir: /staging/nextcloud/NovaseqX/20260922_LH00626_0134_B22MWJHLT1

2. Provision the environment once (creates .pixi/ from pixi.toml / pixi.lock):
     pixi install

3. Make the script executable and check it by hand (it should print "waiting for ..."
   until the sequencer finishes, and must not create .auto_launched):
     chmod +x <run_dir>/run_when_ready.sh
     <run_dir>/run_when_ready.sh

4. Add half-hourly entries with 'crontab -e'. cron has no start date, so bound the schedule with
   day-of-month/month fields. Example: start at 06:00 on Sep 24, keep checking through Sep 30:
     */30 6-23 24 9 * <run_dir>/run_when_ready.sh >> <run_dir>/logs/cron_run.log 2>&1
     */30 * 25-30 9 * <run_dir>/run_when_ready.sh >> <run_dir>/logs/cron_run.log 2>&1
   where <run_dir> is e.g. /staging/nextcloud/testing_illumina/NovaSeqX/xR118

5. After the run has published, remove its lines from the crontab. A dated entry such as
   `0 6 24 9 *` fires again every year if left behind.

Notes:
- Publish really sends the per-order emails. The .auto_launched sentinel (created just
  before `pixi run all`) makes every later cron tick a no-op, so customers are never
  re-mailed. Delete it only to deliberately re-run all + publish.
- .auto_launch.lock (flock) stops an hourly tick from starting a second copy while a long
  run is still in progress.
- Logs: logs/cron_run.log (cron wrapper), logs/driver/ (snakemake), logs/publish_*.log.
- cron runs with a minimal PATH. The script resolves pixi automatically, falling back to
  $HOME/.pixi/bin/pixi, so no PATH edits are required in crontab.
- DRAGEN is referenced by absolute path (dragen_bin in the project config); it must be
  installed on this host (not provisioned by pixi). This is why the job runs here via cron
  and not under Slurm: bcl-convert needs this machine's DRAGEN FPGA and local /staging.
- monitor_and_run_snakemake.sh (tmux launcher, `pixi run all` only) is the older approach.
